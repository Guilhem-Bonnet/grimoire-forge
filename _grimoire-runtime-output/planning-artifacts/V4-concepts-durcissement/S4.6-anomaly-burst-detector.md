# S4.6 — Anomaly burst detector hooks

## Objectif livrable

Un détecteur de burst (sliding window + threshold + cooldown) intégré au
hook `grimoire-subagent-trace.sh`. Quand un même `(agent, event_name)`
dépasse le seuil dans la fenêtre, un `GrimoireEvent` `scope=anomaly,
phase=info` est émis via le canal canonique
(`grimoire-emit-event.sh`), préservant la garantie single-writer sur
`activity.jsonl`.

## Chemin de preuve

- Module `grimoire/tools/anomaly_burst.py` : `record(state, agent, event,
  now, threshold, window, cooldown) → (state, anomaly | None)` pur,
  testable.
- CLI `python -m grimoire.tools.anomaly_burst record/inspect` : exit-0
  fail-open, JSON `{"anomaly": null|{...}}` sur stdout.
- État JSON persisté dans
  `_grimoire-runtime-output/hook-runtime/anomaly-burst-state.json`,
  rotation par fenêtre + cap à 1000 entrées.
- Hook `grimoire-subagent-trace.sh` : appel CLI après chaque event, parse
  la sortie JSON, transmet l'anomalie au gateway si présente.
- Tests : 19 unitaires (pruning, détection, cooldown, isolation
  agent-par-agent, state I/O, CLI end-to-end).

## Dépendances

- V1 bus d'événements (`grimoire.tools.events`, scope `anomaly` déjà
  défini dans le schéma).
- `grimoire-emit-event.sh` (writer canonique).
- `grimoire-subagent-trace.sh` (point d'instrumentation).

## Out of scope

- Détection multi-pattern (e.g. alternance pathologique entre agents) →
  V5+.
- UI dédiée (la consommation passe par les surfaces lisant
  `activity.jsonl`).
- Auto-throttling / kill-switch — le détecteur est observationnel
  uniquement à ce stade (pas de `decision: block`).

## Paramètres par défaut

- `window_seconds = 120` (2 min)
- `threshold = 8` (8 events identiques dans la fenêtre)
- `cooldown_seconds = 300` (5 min, évite le spam d'anomalies)
