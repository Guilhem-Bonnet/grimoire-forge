01 · MANIFESTE
01

La traçabilité n'est pas une option.

Chaque décision d'agent, chaque artefact émis, chaque contrat signé — tout est enregistré dans le runtime. Pas de boîte noire. Pas d'approximation.

02

Un runtime, pas une collection d'appels API.

Grimoire Forge n'enchaîne pas des LLM. Il forge une surface de contrôle cohérente où les agents opèrent selon des contrats définis, dans un espace mémoire partagé.

03

Les artefacts sont la seule mesure de réalité.

Un agent qui répond n'accomplit rien. Un agent qui émet un artefact versioné, validé et adressable — lui, produit du réel. Forge optimise pour l'artefact, pas pour la conversation.

03 · ANATOMIE

Du signal à l'artefact.

Quatre couches. Un flux. Chaque composant respecte un contrat d'interface strict — pas de couplage implicite.

04 · FLUX

De l'idée à l'artefact.

01

Formulation du contrat

L'opérateur définit l'objectif, les outils autorisés et les critères de validation. Le runtime valide la signature du contrat avant toute exécution.

02

Frappe des agents

Le scheduler sélectionne et spawne les agents selon le contrat. Chaque agent reçoit un contexte mémoire délimité et une directive précise.

03

Exécution du pipeline

Le runtime orchestre la séquence d'appels, gère les dépendances entre agents et enregistre chaque décision dans le trace ledger.

04

Émission de l'artefact

L'artefact final est versioné, adressable et signé par le contrat. Il est disponible dans l'Observatory et exportable via l'API.

05 · CAPACITÉS

Un noyau. Neuf capacités de précision.

Contrats typés

Chaque agent opère selon un contrat déclaratif validé au runtime. Aucun appel non autorisé. Aucune dérive silencieuse.

LIRE LA SPEC →

Trace immutable

Chaque décision, chaque appel, chaque transition d'état est enregistrée dans un ledger append-only. Auditabilité totale.

EXPLORER LA TRACE →

Scheduler adaptatif

Le SOG route agents et modèles selon l'intention et le contrat (routing task-aware), décompose la tâche en sous-étapes et dispatche en concurrence.

VOIR LE SCHEDULER →

Open Surface Protocol

Les surfaces sont des plugins. N'importe quel builder peut exposer une surface custom via le protocole WS standardisé.

PROTOCOL SPEC →

Artefacts versionés

Chaque émission est versionnée, adressable par hash et liée à la trace qui l'a produite. Reproductibilité garantie.

API ARTEFACTS →

Memory bus partagé

Memory OS partagé : couche chaude Redis, sémantique Weaviate, graphe Neo4j, sidecar SQLite. Types logiques accessibles aux agents d'une session, isolés par namespace.

MÉMOIRE API →

Multi-session RBAC

Isolation par session, rôles opérateurs configurables et audit trail par tenant. Modèle multi-tenant en cours de durcissement pour la War Room (Q3 2026).

RBAC SPEC →

Observabilité native

Métriques de pipeline, latence par agent, taux d'émission d'artefacts — exposés en OpenTelemetry sans instrumentation supplémentaire.

MÉTRIQUES →

Model-agnostic

OpenAI, Anthropic, Google, local via Ollama — le runtime abstrait le modèle. Les contrats restent valides quelle que soit la coulée.
