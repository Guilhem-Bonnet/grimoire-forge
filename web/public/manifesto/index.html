MANIFESTO · POURQUOI GRIMOIRE FORGE

Un noyau agentique traçable, pour des builders qui refusent le magique.

Grimoire Forge ne remplace ni ton IDE, ni ton agent de code favori. C'est le runtime qui rend auditable tout ce que font tes agents : quel outil, pour quel prompt, avec quelle décision, quelle contradiction, et quel artefact sort à la fin.

Le problème qu'on résout.

Les agents de code deviennent puissants. Le workflow qui va avec reste fragile et opaque. On empile un chat, un terminal, un IDE, un hook de pre-commit, un CI, et chaque outil voit un fragment différent de ce que l'agent a réellement décidé.

Quand une session produit un bug subtil, un choix d'architecture discutable ou une régression silencieuse, tu ne peux pas rejouer la conversation. Tu ne peux pas montrer à un reviewer pourquoi l'agent a tranché. La décision est perdue entre le prompt et le diff.

Grimoire Forge fait l'inverse : chaque outil invoqué, chaque sous-agent dispatché, chaque contradiction détectée est écrite dans un journal d'événements (activity.jsonl) avant d'être consommée par une surface (cockpit, observatory, kanban). Le runtime est la source de vérité. Les UIs sont des lecteurs.

Quatre principes non négociables.

01 · TRACE-FIRST
Aucune action sans événement.
Chaque appel d'outil, chaque sous-agent, chaque compaction produit un événement versionné schema_version=1.0. Pas de magie, pas de zone grise. Si ce n'est pas dans le ledger, ça n'a pas eu lieu.
02 · CONTRACT-DRIVEN
Les interfaces sont signées.
WebSocket cockpit, bus d'événements, projections pures : tout passe par des contrats Zod validés. Un hook qui casse le contrat est rejeté avant d'atteindre une surface.
03 · RENDERER-AGNOSTIC
La logique ignore le pixel.
Les projections TypeScript (office-view, pheromone-panel, timeline-scrubber) ne touchent ni au DOM ni au fs. Le cockpit Svelte, le dashboard local, un CLI texte : trois vues d'un même état.
04 · COMPOSABLE · OUVERT
Ton stack reste ton stack.
Grimoire s'installe à côté de ton IDE, pas à la place. Ton éditeur, ton agent de code et ta chaîne git restent pilotables. Le runtime orchestre, il ne captive pas.

Quand Grimoire n'est pas le bon choix.

On préfère être honnête plutôt que large. Évite Grimoire si :

  • Tu cherches une expérience IDE clef-en-main, prête à l'emploi, sans couche d'orchestration à configurer.
  • Ton besoin se limite à "un agent qui écrit du code" sans exigence d'audit ou de rejouabilité.
  • Tu ne veux pas manipuler de config YAML, de hooks shell, ou de contrats versionnés. Grimoire est transparent par design — donc explicite.
  • Tu n'as pas l'intention d'exposer plusieurs surfaces sur la même session (cockpit, observatory, kanban) ; un seul chat suffit.

À l'inverse, si tu multiplies les agents, tu veux prouver une décision a posteriori, ou tu construis un produit qui exige des artefacts signés, Grimoire a été pensé pour toi.
